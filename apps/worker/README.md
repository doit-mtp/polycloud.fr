# Worker: api.polycloud.fr

Backend of the site's forms (currently the sponsor form), built with [Hono](https://hono.dev) and [Zod](https://zod.dev). It checks the Turnstile token and the fields, stores the request in D1, then emails it to the team through Resend. Every Monday a cron deletes the requests older than 3 years.

It is deployed with Wrangler: `wrangler.jsonc` holds the whole configuration (custom domain, bindings, cron).

## Layout

| Path                        | Role                                                          |
| :-------------------------- | :------------------------------------------------------------ |
| `src/index.ts`              | Worker entry: HTTP handler and weekly cron                    |
| `src/app.ts`                | Hono app: allowed origins, CORS, routes, errors               |
| `src/lib/`                  | Error responses, Turnstile check, Resend client               |
| `src/forms/index.ts`        | Mounts every form under `/forms`                              |
| `src/forms/middleware.ts`   | Shared checks: JSON only, size limit, field errors, Turnstile |
| `src/forms/fields.ts`       | Shared zod fields, with French messages                       |
| `src/forms/sponsor/`        | Sponsor form: route, schema, D1 queries, email                |
| `migrations/`               | D1 schema                                                     |
| `worker-configuration.d.ts` | Runtime and `Env` types, generated by `pnpm types`            |

### Adding a form

1. Create `src/forms/<name>/` with a zod schema built from `fields.ts`, and a router whose `POST /` chains `requireJson`, `limitBody`, `formBody(schema)` and `requireHuman` before its handler (see `sponsor/route.ts`).
2. Mount it in `src/forms/index.ts`: `forms.route('/<name>', router)`.
3. Add a migration in `migrations/` if it stores data.

## API

Every form is posted as JSON to `POST /forms/<name>`, with the Turnstile token (`cf-turnstile-response` on the page) in the `Turnstile-Token` header. The fields are checked before the token, so a visitor fixing a field does not need a new one.

Success: `201 { ok: true }`. Errors: `{ ok: false, error: <code> }`, plus `fields` (French message per field) for `invalid_fields`.

| Status | `error`                  | When                                     |
| :----- | :----------------------- | :--------------------------------------- |
| 400    | `invalid_fields`         | Some fields are invalid (see `fields`)   |
| 400    | `invalid_body`           | Not a JSON object                        |
| 403    | `forbidden_origin`       | Origin not in `ALLOWED_ORIGINS`          |
| 403    | `turnstile_failed`       | Turnstile token missing or refused       |
| 404    | `not_found`              | Unknown path                             |
| 405    | `method_not_allowed`     | Method other than `POST`                 |
| 413    | `payload_too_large`      | Body over 32 KB                          |
| 415    | `unsupported_media_type` | `Content-Type` is not `application/json` |
| 500    | `server_error`           | Unexpected failure (logged)              |

### `POST /forms/sponsor`

```ts
{
  company: string; contactName: string; email: string;
  tier: string; // a tier id from apps/site/src/data/sponsoring.ts, which also gives its label
  website?: string; role?: string; phone?: string; message?: string;
}
```

## Development

```sh
cp .dev.vars.example .dev.vars
pnpm db:migrate   # creates the local D1 schema
pnpm dev          # http://localhost:8787
```

| Command                  | Does                                                          |
| :----------------------- | :------------------------------------------------------------ |
| `pnpm typecheck`         | Type-checks the source                                        |
| `pnpm types`             | Regenerates `worker-configuration.d.ts` after a config change |
| `pnpm deploy`            | Bundles and deploys the Worker                                |
| `pnpm db:migrate:remote` | Applies the new migrations to the production database         |

Run `pnpm db:migrate:remote` before `pnpm deploy` when a change adds a migration.

## First deployment

Wrangler needs to be logged in (`pnpm wrangler login`), or `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` set.

1. Create the database, in the EU since it stores personal data (the jurisdiction cannot be changed later), and put the printed `database_id` in `wrangler.jsonc`:

   ```sh
   pnpm wrangler d1 create polycloud-sponsor-requests --jurisdiction eu
   ```

2. Create the tables: `pnpm db:migrate:remote`.
3. Create a Turnstile widget for `polycloud.fr` in the Cloudflare dashboard. Its site key goes on the form, its secret in the Worker.
4. Deploy, then set the secrets:

   ```sh
   pnpm deploy
   pnpm wrangler secret put TURNSTILE_SECRET
   pnpm wrangler secret put RESEND_API_KEY   # Resend key with sending access
   ```

Read the latest requests:

```sh
pnpm wrangler d1 execute DB --remote \
  --command "SELECT created_at, company, tier_label, email FROM sponsor_requests ORDER BY id DESC LIMIT 20"
```
